\chapterAndLabel{Delegation Checker}{delegation-checker}

The Delegation Checker verifies that a class that is written as a
\emph{delegator} really does delegate.  A delegator is a class that
implements each method $m$ that overrides a supertype method by calling $m$
on the \emph{delegate}.  Delegation
is an alternative to
inheritance:  rather than reusing a superclass's implementation, the
delegator forwards each call to an object that it wraps.

Here is an example of a delegator:

\begin{Verbatim}
class MyEnumeration<T> implements Enumeration<T> {
  @Delegate private Enumeration<T> e;

  public boolean hasMoreElements() {
    return e.hasMoreElements();
  }

  public T nextElement() {
    return e.nextElement();
  }
}
\end{Verbatim}

Delegation is worth verifying because other reasoning depends on it.  A
delegator must satisfy the specifications of the supertype methods that it
overrides, and it does so because the delegate satisfies them.  For
example, suppose that \<Enumeration.hasMoreElements()> has a conditional
postcondition.  Then \<MyEnumeration.hasMoreElements()> satisfies that
postcondition only because its body is exactly a call to
\<e.hasMoreElements()>.  A typo, an extra side effect, or a forgotten
override silently invalidates the reasoning that another type-checker
performs.  The Delegation Checker detects such mistakes.

The Delegation Checker is not a type system:  it defines no type
qualifiers and no subtyping relationship.  It is nonetheless a checker, and
it is run in the same way as any other checker.


\sectionAndLabel{Running the Delegation Checker}{delegation-checker-running}

An example invocation is

\begin{Verbatim}
javac -processor org.checkerframework.common.delegation.DelegationChecker MyFile.java
\end{Verbatim}

The Delegation Checker's purpose is to justify reasoning that
\emph{other} checkers perform, so it is most useful when run together with
the type-checkers whose specifications the delegator depends on:

\begin{Verbatim}
javac -processor NullnessChecker,DelegationChecker MyFile.java
\end{Verbatim}


\sectionAndLabel{Annotations}{delegation-checker-annotations}

The Delegation Checker uses the following declaration annotations:

\begin{description}
\item[\refqualclass{common/delegation/qual}{Delegate}]
  is written on a field.  It indicates that the field is the delegate of
  the class that declares it:  each implementation of an overriding method
  calls the same method on
  the field.  A class can have at most one \<@Delegate> field.
\item[\refqualclass{common/delegation/qual}{InheritableByDelegator}]
  is written on a method.  It indicates that the method's implementation is
  correct for a delegator that inherits it, so a delegator need not
  override the method.  Write it on a method whose body uses its receiver
  only by calling overridable methods on it.  Dynamic dispatch sends those
  calls to the delegator's overriding implementations, which forward them
  to the delegate.  For example, a delegator that overrides \<size()> can
  inherit this implementation of \<isEmpty()>:
\begin{Verbatim}
  @InheritableByDelegator
  public boolean isEmpty() {
    return size() == 0;
  }
\end{Verbatim}
\end{description}


\sectionAndLabel{What the Delegation Checker guarantees}{delegation-checker-guarantees}

Within a class that declares a field annotated \<@Delegate>, the Delegation
Checker enforces the following rules.

\begin{itemize}
\item
  The class declares at most one field annotated \<@Delegate>.  Otherwise,
  the checker issues a \<multiple.delegate.annotations> error.
\item
  The body of every method that overrides (or implements) a supertype
  method consists of a single statement, which is
  \begin{itemize}
  \item
    a call to the same method on the delegate field, passing the
    overriding method's formal parameters, in order, as the arguments; or
  \item
    \<throw new UnsupportedOperationException(...)>.  A delegator can
    refuse to support an operation rather than delegating it.
  \end{itemize}
  Otherwise, the checker issues an \<invalid.delegate> warning.
\item
  The class overrides every concrete method that it would otherwise
  inherit from a supertype, except methods that are annotated
  \<@InheritableByDelegator>.  Otherwise, the checker issues a
  \<delegator.must.override> warning that lists the methods that were not
  overridden.  The reason is that an inherited implementation generally
  reads the receiver's fields, which hold the delegator's own state rather
  than the delegate's.  The class need not override a method that it
  cannot override (a final or static method), a default method of an
  interface (which cannot read instance fields), or a method of \<Object>
  (which has no fields).
\end{itemize}

A class with no field annotated \<@Delegate> is not a delegator, so the
Delegation Checker does not apply the above rules to it.

In every class, the Delegation Checker verifies each method that is
annotated \<@InheritableByDelegator>:  the method uses its receiver only as
the receiver of a call to a method that is overridable or that is itself
annotated \<@InheritableByDelegator>.  For example, the method does not
read a field, call a private or final method, call a method on \<super>, or
pass \<this> as an argument.  Otherwise, the checker issues an
\<invalid.inheritable.by.delegator> warning.  A package-private method is
treated as not overridable, because a delegator in a different package
cannot override it.


\sectionAndLabel{Example}{delegation-checker-example}

\begin{Verbatim}
import java.util.IdentityHashMap;
import java.util.Map;
import org.checkerframework.common.delegation.qual.Delegate;

public class MyMap<K, V> extends IdentityHashMap<K, V> {

  @Delegate private final IdentityHashMap<K, V> map;

  MyMap(IdentityHashMap<K, V> map) {
    this.map = map;
  }

  @Override
  public int size() {
    return map.size();     // OK: delegates
  }

  @Override
  public V get(Object key) {
    return map.get(key);   // OK: delegates, passing the formal parameter
  }

  @Override
  public boolean isEmpty() {
    // Warning: the body is not a call to map.isEmpty()
    return map.size() == 0;
  }

  @Override
  public void putAll(Map<? extends K, ? extends V> m) {
    // OK: a delegator can refuse to support an operation
    throw new UnsupportedOperationException();
  }
}
\end{Verbatim}
